# 저장된 분석 JSON 검토·비교

검증일: 2026-10-16. 기존 분석 결과를 파일로 남기고 나중에 검토하는 흐름을 추가했습니다.

## 사용 방법

1. ZIP 분석 또는 GitHub 변경 분석을 실행하고 `JSON 결과 저장`으로 결과를 저장합니다.
2. `저장된 JSON 검토·비교`를 펼쳐 기준·비교 파일을 각각 선택합니다. 현재 분석 결과를 바로 두 슬롯에 보관할 수도 있습니다.
3. 다른 업로드에서 나온 일반 분석을 비교하려면 같은 프로젝트인지 확인하고 양쪽에 동일한 프로젝트 비교 키를 지정합니다. 현재 결과에 붙일 키는 내보내는 JSON에도 포함됩니다.
4. 공통 변경 시작점·분석 범위를 선택하면 영향 후보 추가·제외·근거 및 위치 변경, 테스트 후보 증감, CRI 차이를 확인할 수 있습니다.
5. `검토 내용 열기`는 읽기 전용 HTML 미리보기입니다. 각 파일을 HTML 또는 정규화한 JSON으로 다시 저장할 수 있습니다.
6. `비교 HTML 보고서 저장`으로 선택한 범위의 증감 전체와 양쪽 파일 정보를 하나의 독립 HTML로 저장합니다. [비교 보고서 사용법과 검증](COMPARISON_REPORT_2026_10_16.md)을 참고하세요.
7. `검토 기록 편집`에서 판단·이유·그래프 내 누락 후보를 남기고 JSON으로 보관합니다. [검토 기록 사용법](REVIEW_NOTES_2026_10_17.md)을 참고하세요.

파일은 브라우저에서 읽으며 분석 API로 전송하지 않습니다. 기존 서버 분석 세션과 선택 노드는 바뀌지 않습니다. 새 화면에서도 프런트엔드가 로드된 뒤에는 서버 연결 없이 사용할 수 있습니다. 두 슬롯은 메모리에만 유지되므로 새로고침 전에 필요한 결과를 파일로 저장해야 합니다.

## 입력 및 비교 조건

- 파일당 UTF-8 기준 최대 10MiB. 현재 JSON 구조의 버전 없는 파일과 `formatVersion: 1`을 지원합니다. 임의의 과거 스키마 전체를 지원하는 것은 아닙니다.
- 그래프 ID 중복, 누락된 참조, 잘못된 타입·범위·날짜·분석 모드, 비정상 배열 크기를 검사합니다. 그래프는 노드 50,000개·간선 200,000개 이하이며 전체 배열 행 예산도 적용합니다. 잘못된 파일을 선택해도 기존 슬롯은 유지됩니다.
- 일반 분석은 같은 변경 시작점과 범위·깊이여야 합니다. 업로드 ID가 다르면 동일한 프로젝트 비교 키가 필요합니다. 어느 한쪽에 키가 있으면 양쪽 키가 일치해야 합니다.
- GitHub 보고서는 같은 저장소와 같은 PR 또는 동일한 커밋 HEAD SHA여야 합니다. PR의 업데이트된 HEAD는 비교할 수 있지만 HEAD/BASE 매핑 방향, revision 상태, 소스 검증 상태와 분석 범위·깊이는 같아야 합니다. 분석 시작점이 없는 보고서는 증감을 계산하지 않습니다.
- 메서드는 소유 클래스·이름·매개변수, 클래스는 정규 이름으로 대응합니다. 해당 속성이 없으면 타입과 정확한 ID를 사용합니다. 의미 식별자가 모호하면 비교를 중단합니다. 이름·시그니처 변경은 추가/제외로 나타날 수 있습니다.
- 여러 GitHub 시작점의 영향 후보는 합치고 변경 시작점 자체는 제외합니다. GitHub CRI는 개별 시작점의 최댓값입니다.
- 근거·위치 변경은 이름·타입·파일·줄·깊이·신뢰도·관계·방향의 변화입니다. 기능 변경이나 장애를 판정하지 않습니다. 경로 전체의 차이를 별도 판정하는 기능은 없습니다.

프로젝트 키, 업로드 ID, GitHub 검증 상태는 파일에 기록된 자기 표기입니다. 불러오기 자체가 소스·서명·분석기 버전을 다시 검증하지 않으며 CRI 변화의 원인을 소스 변경으로만 단정할 수 없습니다. CRI는 상대 위험지수입니다. 입력의 알려진 루트 필드만 재구성하며 현재 화면의 토큰 상태는 저장하지 않습니다. 파일 내용 전체에 비밀정보가 없음을 보증하는 기능은 아닙니다.

HTML은 텍스트 이스케이프와 CSP를 적용하고 미리보기는 스크립트 실행 권한이 없는 sandbox iframe으로 표시합니다. 큰 HTML은 미리보기를 생략하고 다운로드를 제공합니다.

## 이번 실행에서 확인한 결과

- `node tools/snapshot-unit.cjs`: 스키마·범위·참조·용량 검사, 기존 형식 호환, 안정 식별자, 프로젝트·범위·깊이·PR 매핑 비교 조건, 중복 의미 식별자 차단 통과.
- `node tools/report-unit.cjs`: 기존 HTML 생성 회귀 통과.
- Chromium 저장 JSON 브라우저 검사: 서버 연결 없이 불러오기·증감 비교, 사용자 비교 키, 잘못된 파일·10MiB 초과 입력 시 기존 결과 유지, 텍스트 이스케이프·sandbox, JSON 재저장, 모바일 폭 검사 통과.
- 기존 전체 UI smoke, 프런트엔드 빌드, backend/frontend semantic 검사 통과.
- 실제 Spring Petclinic ZIP: 241개 노드의 단일 영향 분석 및 3단계 비교 JSON을 내보내고 현재 결과 보관·재불러오기 통과. 새 화면에서 서버 연결을 끊고 FEATURE 결과 차이가 0임을 확인했으며 서버 분석 세션은 복원되지 않았습니다.

실제 서버 검사에는 backend 8080, frontend 5173과 `.benchmark-cache/spring-petclinic.zip`이 필요합니다.

```powershell
$env:BROWSER_CHANNEL='chromium'
node tools/snapshot-unit.cjs
node tools/run-ui-smoke.cjs snapshot-browser-smoke.cjs
node tools/snapshot-live-smoke.cjs
```

실제 산출물은 Git 제외 경로 `benchmark-output/live-impact-snapshot.json`, `live-comparison-snapshot.json`, `saved-review-live.png`에 생성됩니다. CI에는 단위 검사와 서버 없는 Chromium 검사를 추가했습니다. 원격 Actions, 배포 및 설치본 재생성은 이번 단계에서 실행하지 않았습니다.
