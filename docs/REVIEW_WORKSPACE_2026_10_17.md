# 브라우저 검토 자동 보관·복구

## 사용 방법

`저장된 JSON 검토·비교`에서 기준·비교 파일을 불러온 다음 `이 브라우저에 검토 자동 보관`을 선택합니다. 처음에는 꺼져 있습니다. 현재 슬롯과 이후 수정 내용을 이 기기의 브라우저 IndexedDB에 보관하며 서버에는 보내지 않습니다. `보관 완료` 표시를 확인한 다음 새로고침하거나 창을 닫으세요.

같은 브라우저·프로필·주소로 접속하면 기준·비교 파일, 각 프로젝트 비교 키, 저장한 판단·이유·검토자 표기를 복구합니다. 현재 서버 분석 세션은 복원하지 않습니다. 편집을 다시 열어 계속 검토할 수 있습니다. 자동 보관을 끄거나 `브라우저 보관본 지우기`를 누르면 브라우저 보관본을 삭제하고 현재 화면의 슬롯은 유지합니다. 슬롯의 `제거`는 자동 보관 중인 해당 슬롯에도 반영됩니다.

자동 보관은 `기록 저장`으로 반영한 판단을 대상으로 합니다. 아직 저장하지 않은 판단·이유·검토자 입력 초안, 편집기 선택 위치, 현재 서버 결과와 인증 정보는 보관하지 않습니다. 변경을 묶어 보관하기 위해 300ms 기다린 뒤 쓰며, 완료 전에 새로고침하면 마지막 완료 지점까지만 복구할 수 있습니다. 브라우저 데이터 삭제·시크릿 모드 종료·저장 공간 정책에 따라 보관본이 사라질 수 있으므로 공유·백업에는 JSON 파일 저장을 사용하세요. 다른 기기·브라우저·프로필·주소·포트로 동기화하지 않습니다.

## 실패·여러 탭 처리

- 보관 완료는 IndexedDB 트랜잭션이 성공한 뒤에만 표시합니다. 쓰기 실패 시 현재 화면의 검토를 유지하며 `다시 보관` 또는 JSON 저장을 안내합니다.
- 브라우저 보관본을 읽을 수 없어도 JSON 불러오기·검토·내보내기는 계속 사용할 수 있습니다. 손상된 보관본을 지운 뒤 다시 켤 수 있습니다. 브라우저 자체가 저장을 막는 경우에는 JSON 저장을 사용합니다. 보관소 열기 응답은 최대 5초 기다립니다.
- 복구할 때도 일반 JSON 불러오기와 같은 필드·버전·참조·10MiB 제한 검사를 적용합니다. 두 슬롯 중 하나라도 잘못되면 일부만 복구하지 않고 오류를 표시합니다. 보관본을 읽는 것만으로 새 버전을 쓰지 않습니다.
- 다른 탭이 더 최신 내용을 저장했다면 오래된 탭의 쓰기를 차단합니다. 현재 검토를 JSON으로 저장한 뒤 새로고침해 최신 보관본을 읽으세요. 탭 간 내용을 자동 병합하지 않습니다. 보관본 지우기는 이 주소의 공유 보관본을 삭제하므로 다른 탭의 후속 쓰기도 충돌로 차단됩니다.

## 검증

Chromium에서 기본 비활성, 양쪽 슬롯과 검토 기록의 새로고침 복구, 서버 세션 미복원, 여러 탭 간 최신 내용 보호, 실제 쓰기 트랜잭션 중단 후 기존 보관본 유지와 재시도, 슬롯 제거, 전체 보관 해제, 손상 데이터 거부, 저장소 접근 거부 중 JSON 사용, 390px 화면을 검사합니다. 검토 중 분석 API를 호출하지 않는 것도 확인합니다.

```powershell
$env:BROWSER_CHANNEL='chromium'
node tools/run-ui-smoke.cjs review-workspace-browser-smoke.cjs
```
