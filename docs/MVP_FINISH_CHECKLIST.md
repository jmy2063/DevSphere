# DevSphere AX 제출·발표 MVP 완료 체크리스트

이 문서는 혼자 작업할 때의 완료 기준이다. 대상은 **Java 17 / Spring Boot 프로젝트의 정적 변경 영향 분석과 GitHub PR·Commit 검토**다. 새 기능보다 아래 흐름의 재현성과 결과 설명을 우선한다.

## 이번에 완성할 사용자 흐름

1. Spring 프로젝트 ZIP을 업로드하고 분석된 노드와 관계를 확인한다.
2. 변경 시작점을 골라 LOCAL / FEATURE / SYSTEM 영향을 비교한다.
3. 영향 후보, 테스트 후보, 소스 경로·줄 번호와 근거 경로를 확인한다.
4. GitHub PR 주소 또는 Commit을 분석해 변경 파일의 매핑 상태와 ZIP 소스 검증 결과를 확인한다.
5. JSON 결과를 저장한다. Web 실행이 어려운 발표 환경에서는 Standalone HTML Demo를 사용한다.

CRI는 **그래프 근거 기반 상대 위험지수**이며 장애 발생 확률이 아니다. 테스트 목록은 실행 결과나 커버리지 증명이 아닌 검토 후보이다.

## 완료 판정

모든 항목에 실제 실행 기록이나 산출물 링크를 남긴 후에만 제출본을 완성으로 표시한다.

- [ ] **실제 사례:** 버전이 고정된 변경 사례 2~3개에서 사람이 예상 영향·테스트를 먼저 기록하고, 결과의 누락·오탐과 근거 경로를 검토한다. 결과와 한계를 문서화한다.
- [ ] **치명적 문제:** 위 사례와 전체 시연 흐름에서 발견한 업로드 실패, 잘못된 소스 매핑, 결과 유실, 실행 중단을 해결하거나 재현 가능한 제한으로 기록한다.
- [ ] **자동 검증:** 최종 커밋에서 GitHub Actions의 기존 Core·benchmark·backend·frontend 검사가 통과한다. 현재 CI에 없는 브라우저 흐름 검사를 추가해 통과시킨다.
- [ ] **설치본:** 최신 소스로 Windows 설치 파일을 다시 만들고 `--verify-payload`, `--self-test`, 새 설치 환경의 실행을 확인한다. 파일 해시와 실행 결과를 기록한다.
- [ ] **발표 재현:** 발표 PC에서 ZIP 업로드 → 영향 비교 → 경로·테스트 확인 → PR/Commit 보고서 → JSON 저장을 순서대로 수행한다. 실패에 대비해 Standalone Demo도 실행한다.
- [ ] **릴리스 정리:** README·시연 자료의 사용법과 한계가 실제 동작과 일치하는지 확인하고, 후속 브랜치를 검토해 `main`에 반영한 뒤 제출 버전을 고정한다.

## 혼자 진행할 순서

1. **실제 사례 검토:** [Ground Truth 평가 계획](VALIDATION_PLAN.md)을 참고하되, 이번 제출의 최소 사례와 30개 이상 정량 평가 목표를 구분한다. 공개 소스 30개 구조 검증은 전체 영향 정확도의 증명이 아니다.
2. **발견한 문제 수정:** 시연 또는 결과 해석을 막는 문제부터 고친다. 각 수정은 재현 절차와 검증 결과를 남긴다.
3. **브라우저 CI 연결:** 현재 [CI 설정](../.github/workflows/ci.yml)에 포함되지 않은 `tools/ui-smoke.cjs`를 자동 실행 대상으로 만든다.
4. **최종 패키징:** [Windows 설치 안내](WINDOWS_INSTALLER.md)에 따라 재빌드·격리 자체 검사·새 환경 실행을 확인한다.
5. **시연·제출:** [START_HERE](../START_HERE.md)의 시연 순서를 새 설치본으로 반복한 뒤 `main` 반영과 제출 파일을 확정한다.

## 이번 제출에서 제외할 확장

다른 언어 분석, 런타임·분산 추적 통합, 대규모 monorepo 증분 캐시, 조직별 권한 관리는 이번 MVP의 완료 조건이 아니다. 정적 분석이 복원할 수 없는 동적 동작과 GitHub 대형 diff의 fallback은 [알려진 분석 경계](KNOWN_LIMITATIONS.md)에 명시한다. 외부 AI와 Neo4j 연결도 핵심 시연의 필수 조건으로 두지 않는다.

## 현재 상태를 해석하는 법

`codex/next-upgrades`의 UX 변경과 기존 CI 성공은 구현·회귀 검증의 근거다. 위의 체크박스는 **최종 제출본에서 새로 확인해야 할 일**이므로 이전 실행 기록만으로 완료 표시하지 않는다. 실제 사례의 독립 정답, 최신 설치본, 발표 PC 실행 결과가 남아야 최종 완료를 선언한다.
