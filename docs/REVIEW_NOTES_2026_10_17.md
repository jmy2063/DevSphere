# 영향 후보 검토 기록

검증일: 2026-10-17. 분석 결과에서 확인한 판단·이유와 누락 후보를 저장한 JSON에 함께 보관할 수 있도록 했습니다.

## 사용 방법

1. `저장된 JSON 검토·비교`에서 파일을 불러오거나 `현재 결과를 기준으로 보관`을 누릅니다.
2. 원하는 기준/비교 카드의 `검토 기록 편집`을 엽니다.
3. 검토할 분석 범위와 대상을 고르고 `영향 확인`, `제외`, `확인 필요`를 선택합니다. `누락 후보 추가`에서는 그래프에 있지만 분석 후보 목록에 없는 대상을 고릅니다.
4. 판단 이유를 입력하고 `기록 저장`을 누릅니다. 제외·누락에는 이유가 필요합니다. 같은 분석·대상을 다시 저장하면 기존 기록을 수정합니다. 저장된 목록에서 기록을 편집하거나 삭제할 수 있습니다.
5. `검토 기록 포함 JSON 저장`으로 파일을 다운로드합니다. 이 파일을 나중에 불러오면 기록이 유지됩니다. HTML 저장과 비교 HTML 보고서에도 기록이 포함됩니다.

기록은 선택한 슬롯의 분석 복사본에 반영됩니다. 상단의 현재 서버 결과 JSON 저장은 별도 결과입니다. 브라우저 메모리의 기록은 새로고침으로 사라지므로 편집 후 위의 JSON 저장 버튼으로 파일을 남겨야 합니다. 검토자 표기는 기록 저장·삭제 시 함께 반영됩니다. 대상이나 범위를 바꾸기 전에 입력한 내용은 `기록 저장`으로 반영하세요.

## 기록과 분석의 관계

- 변경 시작점·분석 범위별로 기록을 분리합니다. 동일한 Node ID에 FEATURE와 SYSTEM의 서로 다른 판단을 남길 수 있습니다. GitHub는 해당 파일의 PR/Commit 변경 집합 단위입니다.
- 미기록 후보 수와 네 가지 판단 수를 보여줍니다. 판단은 사용자의 검토 기록이며 자동 정답·독립 검수·테스트 실행을 뜻하지 않습니다. 검토자 이름도 직접 입력한 표기입니다.
- 기록을 남기거나 제외해도 원본 후보·CRI·Precision/Recall·스냅샷 증감은 바뀌지 않습니다. Ground Truth로 자동 전환하거나 분석 엔진을 자동 학습시키지 않습니다.
- 누락 후보는 해당 그래프에 이미 존재하는 대상만 선택할 수 있습니다. 그래프 자체에 없는 파일·노드, 현재 변경 시작점, PROJECT/PACKAGE는 추가하지 않습니다.
- 다른 보고서로 기록을 자동 이관하지 않습니다. 비교 HTML은 선택한 분석에 해당하는 기준·비교 측 기록을 따로 표시합니다. 다른 범위의 기록은 해당 비교 HTML에 섞이지 않습니다.
- 검토자 표기는 보고서 전체에 적용하며, 다중 사용자 인증·서명·편집 이력 관리는 제공하지 않습니다. 원본 분석과 기록의 출처·변조 여부를 재검증하지 않습니다.

## 저장 형식과 제한

기존 `formatVersion: 1` JSON에 선택적인 `review` 필드를 추가했습니다. 기록이 없는 기존 파일도 그대로 지원합니다. 구버전 프로그램으로 다시 저장하면 알지 못하는 검토 필드가 사라질 수 있습니다.

- `review.version`: 1
- `review.reviewer`: 최대 100자
- `review.entries`: 보고서당 최대 2,000개
- 편집 목록은 처음 50개를 표시하고 버튼으로 나머지를 펼칩니다. JSON·HTML 저장에는 전체 기록을 포함합니다.
- 각 기록: 분석 구분 키, 정확한 그래프 Node ID, 판단, 최대 2,000자의 이유, 기록 시각
- 제외·누락의 빈 이유, 알 수 없는 분석/노드/판단/버전, 중복 분석·대상 기록, 잘못된 시각, 후보/누락 구분 오류를 거부합니다.
- 전체 JSON의 10MiB 제한은 유지합니다. 제한에 걸리는 편집·파일 불러오기는 기존 슬롯을 보존합니다.

알려진 필드만 재구성하고 HTML은 텍스트로 이스케이프합니다. JSON·HTML에는 사용자가 입력한 이름과 이유가 그대로 담기므로 공유 전에 내용을 확인하세요.

## 확인한 결과

- 단위 검사: 기존 파일 호환, 단일·3범위·GitHub 결과의 기록 재불러오기, 분석/노드/상태/이유/날짜/중복/크기 검사, HTML 이스케이프, 범위별 비교 출력, 분석 지표 유지 통과.
- Chromium: 서버 연결 없이 생성·수정·삭제, 필수 이유, 범위 간 분리, 누락 후보, JSON 재불러오기, 개별/비교 HTML, 잘못된 기록이 있는 파일 선택 시 기존 슬롯 보존, 390px 모바일 레이아웃 통과.
- 실제 Spring Petclinic ZIP을 현재 서버에서 분석했습니다. 241개 노드의 분석을 보관하고 후보에 판단을 남겨 JSON으로 저장했습니다. 편집은 분석 API를 호출하지 않았고, 서버 연결을 끊은 새 화면에서 기록과 읽기 전용 HTML을 다시 확인했습니다.
- 프런트엔드 strict 타입 검사·production 빌드 및 기존 UI·저장 JSON·HTML 회귀 검사 통과. 이번 단계에서 분석 엔진 코드는 변경하지 않았습니다.

```powershell
node tools/review-notes-unit.cjs
$env:BROWSER_CHANNEL='chromium'
node tools/run-ui-smoke.cjs review-notes-browser-smoke.cjs
```

실제 서버 검사는 backend 8080, frontend 5173과 공개 Petclinic ZIP을 준비한 뒤 `node tools/snapshot-live-smoke.cjs`로 반복합니다. 로컬 산출물은 Git 제외 경로 `benchmark-output/review-notes-*.{json,html,png}`, `live-reviewed-snapshot.json`입니다. CI에 새 단위·브라우저 검사를 연결했습니다.
